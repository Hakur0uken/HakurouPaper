# 远程协作：首版 Git 凭据

状态：0.8.2 试验功能。已完成真实 Gitee 仓库的 Git 传输测试，原生桌面完整交互与权限异常场景待验收。首版无需注册 OAuth 应用、购买域名或部署服务。

## 使用方式

1. 在 Gitee 或 GitHub 网站创建仓库、邀请成员。每位协作者使用自己的账号。
2. 在外部通过 `git clone` 下载仓库，再在 HakurouPaper 打开其中的 Markdown；软件自动识别仓库、远程地址和当前分支。新项目也可先启用本地版本管理，再在“远程协作”填写仓库地址。
3. 对 HTTPS 仓库，选择“添加 Git 账号”，默认 Gitee。填写个人主页中的用户名，以及平时进行 Git HTTPS 操作使用的密码或令牌。GitHub 使用有目标仓库权限的个人访问令牌，不能使用网页登录密码。
4. 点击“保存凭据”。相同平台及用户名再次保存会更新凭据；同平台只有一个账号时自动选用，多个账号时在“此仓库使用的账号”选择一次。软件按仓库、远程名称和精确平台域名记忆选择。
5. “检查更新”只下载远程记录；“获取更新”要求仓库及打开的文稿没有未保存/未提交修改，且历史可以快进；“上传版本”在确认目标仓库和分支后上传已提交历史。

Gitee 的密码/令牌要求以当前账号安全设置和平台说明为准，请使用已经能完成 Git HTTPS 操作的凭据，不能假设所有 Open API 令牌都能用于 Git。保存成功仅表示本机已保存；公开仓库允许匿名读取，因此“检查更新”成功也不证明此账号身份或写入权限。私有仓库访问和上传以服务端实际响应为准。

选择“使用系统 Git / SSH 身份”可继续使用系统已配置的身份。SSH 地址只使用系统 SSH 密钥，不会自动改成 HTTPS；如需软件内保存的用户名凭据，请使用网站给出的 HTTPS 地址。软件不会开启 Git 的交互式网页登录；系统凭据缺失时会显示错误。

## 保存与移除

- 首版的软件内凭据保存面向 Windows，使用原生 Credential Manager，仅当前用户在本机持久化；其他平台继续使用系统 Git / SSH。
- 本机 `git-accounts/credentials.json` 仅含平台、用户名、账号标识与仓库选择；密码/令牌不写入此文件、仓库地址或 `.git/config`。
- 每次 HTTPS 操作只将所选凭据通过子进程环境传给 Git，授权头限定于选定仓库 URL，禁止重定向；操作结束不留下临时凭据文件。Git trace 环境变量会被清除，传输错误使用固定分类，不展示原始输出。
- “更新凭据”重新输入秘密，界面不会读回旧密码。“移除本机账号”删除本软件保存的系统凭据和账号记录，不注销托管账号，也不删除其他软件保存的凭据。
- 仓库绑定的账号被移除后，必须重新选择身份；不会静默换用另一个账号。
- GitHub 与 Gitee 可同时保存；同平台多个账号分别保存。仓库只有读取权限、令牌过期或分支受保护时，上传仍可能被平台拒绝。

## 范围与边界

本地“创建版本”仍只处理当前文稿及关联资源。远程上传覆盖整个分支的已提交历史，因此同仓库其他文稿的已提交内容也会上传。不会自动提交、强推、自动 stash、变基或解决冲突。

无软件内 clone、创建仓库、邀请成员、分支管理或冲突编辑器。复杂 Git 配置（多个 fetch/push 地址、不同目标或协议、额外地址重写）会要求先在外部整理。多端历史分叉时保留双方版本，需先在 Git 中合并。

## 实现入口

- `src/features/remote-sync/`：独立工作区，中英文界面。
- `src/platform/remoteTypes.ts`、`src/platform/tauri/remoteGit.ts`：宿主接口。
- `src-tauri/src/git_accounts.rs`：公开元数据、账号选择和系统凭据保存。
- `src-tauri/src/remote_git.rs`：检测、显式 fetch、快进更新和单分支上传。

首版已移除未发布的 OAuth 客户端、授权服务及其独立依赖。没有使用旧原型生成的设备密钥；旧原型记录不自动迁移或覆盖。

## 验收

已通过真实 Gitee 仓库的初次克隆、首次及增量推送、另一副本获取更新、文稿和图片一致性检查。仍需完整验证原生界面的首次保存、重启保留、拉取、推送、错误凭据、权限撤销与双账号选择，并验证真实 GitHub 账号的平台隔离。原生桌面需回归网络等待期间编辑、拉取后的文稿及资源刷新、未保存内容保护。临时仓库、回环 HTTP、模拟 UI 及命令行传输测试只能证明对应实现路径，不能替代上述验收。
