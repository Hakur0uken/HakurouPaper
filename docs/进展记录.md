### 已验收：多文稿编辑器叠层事故修复

- 复现路径：启动后点击 `New`，顶部仅新增一个标签，但正文区会纵向叠加欢迎页与上一次文稿；随后切换标签时，叠层内容继续串台。
- 根因一：Milkdown 的 React Provider 生命周期与 React 开发模式重复挂载叠加，旧编辑器异步完成初始化后仍向当前根节点追加 DOM。
- 根因二：编辑器内容回调曾按“当前活动标签”回写，旧实例发出的事件可能污染新标签内容。
- 修复：移除会造成重复挂载的 Strict Mode 与 Milkdown React Provider 包装；改为由 `WritingEditor` 管理独立内部宿主。每个编辑器实例只写入自己的宿主，宿主卸载后旧实例即使晚到也不可见。内容与图片资源回调改为按固定 `documentId` 回写。
- 验证：实际桌面复现后，用户确认 `New → 标签切换` 不再发生正文叠层。

### 开发中：空行插入、分隔线与表格

- 在正文的空白段落左侧增加按需出现的“+”入口，不占用正常写作视野；点击后可插入分隔线或表格。
- 表格采用悬停式 8 × 8 行列选择器，实时显示当前目标尺寸；为符合 Markdown/GFM 的表头语义，最少生成“表头 + 1 行正文”。
- 插入内容由 Milkdown/ProseMirror 结构化节点生成，保存时仍应回写为标准 Markdown；新增分隔线和表格的低对比度细线样式，表格单元格取消段落额外间距。
- 表格行列网格的选中状态由蓝色调整为低饱和墨绿色，保持与 HakurouPaper 界面色彩一致。
- 编辑器末尾新增一次性可落笔逻辑：点击最后一个实际内容节点下方时创建并聚焦一个空段落；末尾已经是空段落时仅聚焦，避免递推式添加空行。该逻辑适用于文字、表格、图片、公式等最后内容节点。
- 图像与表格对象操作（开发中）：鼠标在图片或表格内停留约 200ms 后显示轻量对象控制柄；点击后操作菜单仅在点击外部或执行操作时关闭。图片提供复制、剪切、删除；表格提供全选、复制、剪切、删除，以及“标题行 / 标题列”视觉开关。标题行/列目前只改变当前编辑器中的低饱和背景与字重，不改变 Markdown 表格数据结构，也不承诺保存重开后的视觉状态。
- 悬浮菜单体验修订（开发中）：对象控制柄延长为约 250ms 后出现；表格操作菜单改从控制柄左侧展开。对象控制柄、块菜单、插入菜单、选区菜单与表格尺寸二级菜单均使用窗口边界夹紧/反向展开逻辑，避免靠近窗口边缘时被裁切。表格标题视觉改为直接作用于首行/首列，不依赖内部 `th/td` 类型；表格尺寸选择器的网格空白区域也可按当前高亮行列创建表格。
- 回归修复（2026-08-25，待桌面验收）：此前表格尺寸二级菜单仍采用父菜单内绝对定位，只处理左右方向，靠近底部会被窗口裁切；现改为固定定位并独立计算四边界。此前“末尾可落笔区”事件只绑定在 ProseMirror DOM，长文档新增内容后的底部空白属于外层编辑区，点击不会触发；现将事件绑定到整个编辑区，同时排除悬浮菜单自身的点击，保证每次内容变化后仍可在文末继续落笔。
- 悬浮控制柄可点击性修复（2026-08-25，待桌面验收）：扩展编辑区事件后，鼠标从正文移动到左侧控制柄会被误判为离开正文，状态立即清除，导致无法点击。现对所有已出现的悬浮控件保留状态；离开正文后延迟约 200ms 才收起，进入图片、表格等其他对象时则立即切换对应控制柄。
- 表格菜单状态修订（2026-08-25，待桌面验收）：表格创建二级面板改为在“表格”项目停留约 250ms 后展开；展开后不因 mouseleave 收起，只由外部点击或创建操作关闭。重新点击空行“+”时重置为二级面板关闭、2×2 默认预览。标题行/列开关同时对表格真实首行/首列增加显式视觉类，避免不同 Milkdown DOM 节点类型导致样式未生效。
- 实际窗口核验（2026-08-25）：直接检查运行中的 `target\debug\hakurou-paper.exe`。表格对象菜单已位于其右侧控制柄的左侧；“设置标题列”开关可即时强调首列，测试后已还原开关。此前不应仅凭构建通过宣称该两项已经生效；表格创建二级菜单的 250ms 延迟与外部点击收起仍保留待用户交互验收状态。
- 对象控制位置与标题列修正（2026-08-25，待桌面验收）：用户明确指出此前把表格控制柄放在右侧与文字/图片的左侧入口不一致。现将表格控制柄改为表格左侧，菜单仍以其左侧为优先展开方向并由窗口边界夹紧。标题行/列开关不再依赖重新查找位置后的节点；直接保留真实 `HTMLTableElement`，对首行/首列单元格写入低饱和背景、文字色与字重，避免编辑器重绘后 class 不生效。
- 标题行/列恢复逻辑修订（2026-08-25，待桌面验收）：用户反馈标题列只有字重变化、底色不明显，关闭后也不能可靠恢复。取消依赖 class 清理；标题开关直接复用默认标题行的 `#efeee9 / #3d5747 / 600` 值，并以明确的正文 `#fbfaf7 / #2f2e2a / 400` 值恢复非标题单元格。
- TypeScript/Vite 前端构建已通过；仍需在桌面测试版验证：空行触发位置、分隔线插入、不同表格尺寸、单元格可输入、保存重开及外部 Markdown 兼容性。

### 失败尝试与结论：公式能力

- 曾尝试以 Crepe 的 `CodeMirror + Latex` 特性给当前 Milkdown 核心编辑器叠加公式能力。
- 结果：编辑区出现额外的确认按钮/对号；行内公式未可靠触发；块级公式引入异常 UI；实际输入测试未达到可用标准。
- 结论：不能把 Crepe 的完整公式/代码块 UI 直接嵌入现有极简核心编辑器。
- 当前工作区存在**未提交**的回退修复：恢复稳定 Milkdown 内核、固定状态栏、为标签切换同步内容。该修复尚须在实际桌面窗口完成验收后再提交。
