# HakurouPaper 长期协作手册

## 1. 当前项目目标

构建面向长文档/论文写作的本地 Markdown 编辑器：极简易用、所见即所得、跨平台、低资源占用，并保持 Markdown 与资源目录的开放兼容性。

正式产品名：`HakurouPaper`。

## 2. 当前工作方式

- 项目目录：`E:\个人其他\Hakurou`。
- 远程仓库：`https://github.com/Hakur0uken/HakurouPaper`。
- 环境与位置索引：`docs/环境与位置说明.md`；路径、运行入口或产物位置改变时先更新该文档。
- 用户测试内容：`test/`，不提交、不覆盖、不删除。
- 没有自动保存；仅用未保存标识和关闭前确认保护内容。
- 每个稳定小步完成构建与对应验收后再提交、推送。
- 版本号只随功能或修复发布递增；图标、文案等视觉调整沿用当前功能版本。

## 3. 任务地图

### A. 稳定性基线（最高优先级）

- [ ] 验收当前未提交的编辑器回退、固定状态栏、标签切换内容同步。
- [ ] 建立最小手工回归清单：输入、保存、切换、关闭、窗口控制。
- [x] 修复正文编辑器叠层与跨标签内容污染：编辑器实例使用独立宿主，回调按固定文稿 ID 写入；已由用户实际验收。
- [ ] 继续观察标签切换闪烁，要求不重置内容、不闪白、不丢焦点。

### B. 编辑体验

- [ ] 公式正文接入（待桌面验收）：行内、块级、KaTeX 渲染及双击源码编辑已接入；下一步验收输入、保存重开、错误容错与不影响普通写作。
- [ ] 中英文界面切换（待桌面验收）：顶栏“中 / EN”须同步切换应用文案，保留当前文稿、选区、菜单状态与本机偏好；不改写 Markdown 正文。
- [ ] 外置展示设置（待桌面验收）：表格三线表/标题行列、文本与图片对齐、首行缩进保存在 `assets/<资源标识>/hakurou.json`；验证保存重开及 Markdown 无私有标记。
- [ ] 字体、表格与缩进默认样式（待桌面验收）：查看菜单支持文档 / 默认两级字体、普通 / 三线表和首行缩进 2 字符；验证统一系统菜单字体、紧凑子菜单、250ms 展开、作用域优先级、保存重开、字体缺失回退、仅改正文字重时的自定义应用、标题不受字重影响、单表/单段落覆盖，以及标题/图片/公式不受默认缩进影响。
- [ ] 空白行块菜单（待桌面验收）：空白“+”可完成正文/标题、两类列表、代码块、表格、分隔线；代码块与列表同组，验证每种转换和保存后的标准 Markdown 语义。
- [ ] 选中文本的悬浮格式菜单：标题、粗体、引用、代码块等。
- [ ] 右键格式菜单，降低 Markdown 语法记忆成本。
- [x] 代码块阅读层级：使用低对比度深底色和等宽字体，与正文明确区分但不引入卡片式装饰。
- [ ] 空行插入与基础表格（待桌面验收）：空白段落“+”菜单可插入分隔线，悬停网格选择表格尺寸；待验证编辑、保存重开和外部 Markdown 兼容性，再扩展行列操作。
- [ ] 表格菜单状态（待桌面验收）：二级行列网格延迟约 250ms 展开、外部点击关闭、每次新开“+”重置预览；标题行/列开关应稳定作用于首行和首列。
- [ ] 文稿末尾可落笔区（待桌面验收）：点击最后内容后的空白区域追加一个段落；末尾已有空段落时仅定位，禁止连续点击递推产生空行。
- [ ] 图片与表格对象菜单（待桌面验收）：鼠标进入对象即显示控制柄，菜单外部点击关闭并自动避开窗口边界；完成基础复制、剪切、删除、表格全选与标题行/列视觉开关。展示设置由外置 JSON 持久化，Markdown/Pandoc 正文不含私有标记。
- [ ] 对象控制柄统一（待桌面验收）：文字、图片、表格均从内容左侧出现；表格标题行/列以真实单元格视觉样式呈现，避免仅切换开关但内容无变化。
- [ ] 表格标题视觉恢复（待桌面验收）：标题行/列开启复用默认标题行样式，关闭显式回到正文基线；验证重复开关不残留背景或字重。
- [ ] 悬浮控制柄稳定性（待桌面验收）：行首控制柄离开正文后以约 200ms 缓冲收起，进入控制柄本身保持可点击；对象类型切换仍应立即响应。
- [x] 最近打开文稿：本机保存最多 10 条；File 二级菜单采用延迟悬停打开、外部点击关闭的宽容交互，避免光标跨菜单时意外消失。

- [ ] 图片粘贴（待桌面验收）：已保存文稿的剪贴板图片会写入 `assets/<文稿资源标识>/`，并插入相对路径；尚待实际粘贴、重开与外部兼容性验证。

## 4. 决策记录

| 决策 | 结论 | 原因 |
| --- | --- | --- |
| 应用架构 | Tauri + Rust + Web 前端 | 轻量、跨平台、本地能力强。 |
| 编辑内核 | 当前使用 Milkdown 核心模式 | 基础输入与 Markdown 往返已可用；不直接嵌入 Crepe 全套 UI。 |
| 保存策略 | 仅显式保存 | 用户明确不要自动保存。 |
| 版本策略 | 后续 Git 手动操作优先 | 先保证可控性，避免静默提交造成困扰。 |
| 视觉 | 扁平、细线、低装饰 | 用户偏好接近 VS Code/FishMark 的克制桌面风格。 |
| 公式 | 暂不采用 Crepe 整套 LaTeX 特性 | 已验证会引入额外控件与不可靠行为。 |
| 公式编辑交互 | 双击正文内渲染公式进入源码编辑，不设置独立实验台 | 公式服务于实际文稿；避免维护与正文写作路径重复的实验工作区。 |
| 编辑器挂载 | 使用独立内部宿主管理 Milkdown 生命周期 | 避免 React 组件重建时旧编辑器异步追加 DOM，保证多文稿隔离。 |
| 非 Markdown 展示设置 | 删除线采用 GFM；表格外观、对齐和首行缩进写入 `hakurou.json` 外置元数据 | Markdown 保持纯净，同时让编辑器可恢复展示设置并为全局格式方案留出入口。 |
| 字体、表格与缩进作用域 | 文档设置写入 `hakurou.json` 并优先于本机默认；本机默认值只存本机 | 同时满足整套文稿的默认风格和个别文稿的独立排版，不污染 Markdown。 |
| 自定义字体 | 输入本机已安装的中英文 CSS 字体名称，并可选字重 | 不内置或分发字体文件，避免许可证、体积与跨设备不一致问题。 |
| 界面语言 | 中文与 English 可在顶栏切换，偏好只保存在本机 | 保持文稿内容原样，降低中英文使用者的界面理解成本。 |
| 正式产品名 | HakurouPaper | 统一应用标题、文档、安装包和用户沟通；技术标识 `com.hakurou.paper` 为兼容既有安装保持不变。 |
| 品牌图标 | 用户确认的大型斜向粉色钢笔花瓣 + 深黑墨绿底 | 保留原始花瓣的不对称轮廓与灵动性；不再采用圆角卡片、单独渐变或小尺寸花瓣方案。 |
| 版本纪律 | 视觉微调不递增版本 | 版本号只表达功能/修复发布，当前定为 `0.1.1`。 |

## 5. 新需求如何进入计划

每个新需求记录：用户目标、用户价值、影响范围、依赖、验收场景、状态。高风险项先做隔离原型；通过验收再接入主编辑器。若需求与《设计原则》冲突，先说明冲突并由用户决定优先级。

## 6. 每次协作的收尾清单

- 更新《进展记录》：日期、实际改动、验证结果、失败与风险。
- 更新本手册中的任务状态与决策。
- 检查 `git status`，确认不提交 `test/` 和无关文件。
- 仅在验收完成后提交推送；否则明确保留为未提交的待验收改动。
