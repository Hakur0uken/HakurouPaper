# HakurouPaper 验收原则

本文件约束每次改动的交付标准，尤其防止“编译通过但用户无法使用”的临时版本被误报为完成。

## 1. 状态定义

| 状态 | 含义 |
| --- | --- |
| 设计中 | 已明确目标，尚未写代码。 |
| 开发中 | 代码正在变更，不能供用户作为稳定版本使用。 |
| 待验收 | 已构建，但未完成真实交互验证。 |
| 已验收 | 满足对应验收项，并且没有阻断级已知问题。 |
| 已回退 | 曾尝试但未满足验收，已从稳定路径撤出。 |

只有“已验收”可以表述为“已支持/已完成”。

## 2. 通用门槛

每个提交至少满足：

- TypeScript 构建成功；修改 Rust 或 Tauri 配置时，`cargo check` 成功。
- 不包含用户测试文稿、个人配置、构建产物或无关文件。
- 不破坏新建、打开、保存、输入、撤销、关闭前确认等基础写作路径。
- 提交说明真实反映状态；试验性功能不得用 `feat` 暗示已稳定，除非明确标识为实验。

## 3. 必须真实交互验证的高风险改动

下列改动仅构建通过不足以验收：

| 范围 | 最小验收场景 |
| --- | --- |
| 编辑器/焦点 | 鼠标点击编辑区、连续输入中文与英文、撤销/重做、复制粘贴。 |
| 多文稿 | 新建两个文稿，各输入不同内容，切换三次，确认内容、未保存状态与字符数均正确。 |
| 窗口 | 拖动、最小化、最大化/还原、关闭；未保存关闭必须出现确认。 |
| 状态栏 | 输入足够长内容并滚动，状态栏始终贴底且显示正确。 |
| 界面语言 | 在顶栏分别切换“中 / EN”；菜单、窗口按钮、侧栏、状态栏与悬浮编辑菜单应同步切换，文稿内容、未保存状态、当前选区和打开菜单状态不得丢失；重启后保持最后一次选择。 |
| 字体作用域 | 分别在“文档字体”和“默认字体”选择优雅、现代、标准及自定义字体；当前文稿应立即更新，未设置文档字体的其他文稿继承本机默认值，已设置文档字体的不被覆盖；保存重开后文档选择仍存在。自定义字体仅输入本机字体名称，不应读取、复制或上传字体文件；输入框留空时必须沿用当前字体，仍可只修改正文字重并应用，标题字重不得变化。 |
| 查看菜单视觉 | “文档字体 / 文档表格 / 文档缩进 / 默认字体 / 默认表格 / 默认缩进”、右侧子菜单与“文档面板”使用相同系统界面字体、字号和基础文字色；箭头样式不得影响标签文字。字体选择子菜单宽度应贴合内容，不出现大面积无意义留白。 |
| 表格默认样式 | 分别在“文档表格”和“默认表格”切换普通表格、三线表；没有单表覆盖的表格应立即更新，单表三线表选择仍优先；保存重开后文档默认值保持。 |
| 首行默认缩进 | 分别在“文档缩进”和“默认缩进”选择无缩进、首行缩进 2 字符；仅含文字的正文段落应立即更新，标题、图片和公式块不应缩进；文本选区的单段落设置仍优先，保存重开后文档选择保持。 |
| 公式 | 行内输入、块级输入、渲染、选中后源码编辑、保存后重开、错误公式容错。 |
| 代码块 | 与正文有清晰但克制的底色区分；等宽字体、长行横向滚动和 Markdown 保存语义均正常。 |
| 空行插入 / 表格 | 鼠标进入空白段落才出现“+”；可转换正文、H1–H3、项目/编号列表和代码块，且代码块与列表同组显示；插入分隔线和至少三种表格尺寸均正确；单元格可输入，保存重开与外部 Markdown 打开后表格结构保持。 |
| 表格创建菜单状态 | 在“表格”项目停留约 250ms 后才展开行列网格；展开后移开鼠标仍保持，点击外部才收起；再次打开空行“+”时不带入上次高亮行列。 |
| 文稿末尾落笔 | 分别以文字、图片、公式、表格作为最后内容，点击其下方均可开始新段落；连续点击新的空段落下方不新增第二个空段落。 |
| 图像 / 表格对象菜单 | 鼠标进入对象即出现控制柄；打开菜单后移开鼠标不关闭，点击外部或执行操作才关闭。图片与表格的复制、剪切、删除均不影响相邻内容；表格全选正确，标题行/列仅按开关改变视觉层级；所有浮窗在窗口边缘仍完整可见。 |
| 外置展示设置 | 对表格三线表、标题行/列、文本/图片对齐和首行缩进分别保存、关闭并重新打开文稿；`assets/<资源标识>/hakurou.json` 应恢复显示效果，Markdown 文件不得出现 HakurouPaper 私有标记。 |
| 对象入口一致性 | 文字、图片、表格控制柄均在各自内容左侧出现；表格标题列打开后，首列每一个单元格均有与标题行一致的加深背景、文字色和字重。 |
| 表格标题开关恢复 | 分别开启/关闭标题行与标题列；开启后的单元格使用默认标题行底色，关闭后全部恢复正文背景、颜色和正常字重，不能残留样式。 |
| 行首控制柄 | 鼠标从正文移动到行首控制柄时不应闪退；离开正文后约 200ms 收起；移动到图片或表格对象时立即切换为相应控制柄。 |
| 文件 | 打开 `.md`、另存为 `.md`、重新打开后内容一致；取消对话框不改变状态。 |
| 最近打开菜单 | 停留约 250ms 后展开；展开后鼠标移开仍保持；点击菜单外部、切换顶级菜单或执行项目后收起；最多 10 条，失效路径给出可理解错误。 |
| 图片 | 粘贴图片、生成相对路径、重开/分享包中可见。 |
| Pandoc | 默认导出、指定模板导出、模板样式映射、失败时提供可理解错误。 |
| Git | 未初始化仓库、已初始化仓库、认证失败、冲突、历史恢复均不丢失未保存内容。 |

## 4. 公式功能专门规则

公式是论文写作核心能力，验收必须同时满足：

1. 行内 `$x^2$` 能在输入完成后进入可读渲染态。
2. 块级 `$$ ... $$` 能作为独立公式排版，不出现无意义按钮、图标或框架控件。
3. 用户双击渲染公式后能进入源码编辑；选中公式后也应有明确、轻量的编辑入口。修改后正确重新渲染。
4. 保存内容保持标准 LaTeX Markdown；用外部 Markdown/Pandoc 工具处理不丢失源码。
5. 公式功能不得影响普通文字输入、光标定位、撤销/重做、标签切换或窗口性能。

任何一条失败，公式功能只能标记为“开发中/已回退”，不能交付。

## 5. 交付沟通规则

- 报告时先说明结果和验证范围，再说明限制。
- 明确区分“代码已写”“构建通过”“实际验证通过”。
- 用户反馈严重问题时，优先止损、回退或隔离问题功能；不要继续叠加新功能。
- 对无法在当前回合验证的行为，必须明确请求用户验证或标记待验收。
- 修改产品名、图标或安装包元数据时，必须检查窗口标题、关于菜单、网页标题、搜索栏、开始菜单、任务栏与安装包名称的一致性；图标微调不得擅自改变版本号。
- 环境、路径或构建流程发生变化时，检查《环境与位置说明》是否仍能直接定位项目、源码入口与对应产物。
